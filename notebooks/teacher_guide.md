# IEV CloudLab 教师指导手册
# Teacher's Guide

## 一、平台定位

本平台覆盖智能电动汽车**基础层**仿真实验（CPU可运行），共29个实验，8大模块：
- A（esmini自动驾驶场景）、B（SUMO交通流）、C（FASTSim整车能量）、D（PyBaMM电池）
- E（优化控制）、F（FMI模型交换）、G（ROS 2）、H（场景工程）

**不覆盖**（需GPU，Stage 2）：相机/激光雷达感知、SLAM、Autoware完整栈。

## 二、评分标准建议

### 2.1 实验报告评分（百分制）

| 维度 | 权重 | 评分要点 |
|---|---|---|
| 结果正确性 | 30% | 验证内容checklist是否全过 |
| 结果分析 | 30% | 五、结果分析是否理解到位，能否解释数据 |
| 思考题 | 20% | 三、学生任务中的思考题回答质量 |
| 挑战任务 | 10% | 是否尝试（不强制完成） |
| 规范性 | 10% | 图表、单位、有效数字 |

### 2.2 关键判据速查

| 实验 | 核心判据 | 合格线 |
|---|---|---|
| A1 | 最小TTC | > 1.5s（AEB触发后） |
| A2 | 跟车误差 | < 2.0m |
| A3 | 增强TTC vs 朴素TTC | 增强版通过，朴素版碰撞（预期） |
| B2 | 延误降低 | > 50% |
| B3 | 编队最大间距误差 | < 2.0m（实测1.09m） |
| C1 | UDDS电耗 | 10-20 kWh/100km（实测12.5） |
| D1 | 1C容量 | 4.85Ah ±5% |
| E2 | Pareto解数量 | ≥50个 |

## 三、学生常见误区

1. **A系列**：误以为目标车是"智能"的——实际在ctypes模式下冻结，等价静态障碍物（已诚实声明）
2. **C系列**：忘记切换`py310-fastsim`内核，导致`import fastsim`失败
3. **B3**：曾有学生用try/except吞掉错误"通过"验证——现已加`len(history)`断言防作弊
4. **E系列**：混淆"代理模型优化"与"真实仿真验证"——E1已明确标注
5. **图表中文方框**：不是bug，是matplotlib缺中文字体，属已知限制

## 四、课堂组织建议

### 4.1 翻转课堂
- 课前：学生通读"一、实验原理"+"二、实验目的"
- 课中：动手做"三、学生任务"，讨论"五、结果分析"
- 课后：完成实验报告（重点写结果分析）

### 4.2 三条链作为课程设计
- **车型设计链**（D3→C1→A1）：适合"新能源汽车构造"课程，2周
- **算法开发链**（A2→E3→B3）：适合"智能汽车控制"课程，3周
- **能量管理链**（E4→C4）：适合"汽车能量管理"课程，2周

## 五、平台管理

### 5.1 添加学生
学生用`@zhjpec.edu.cn`邮箱自助注册，用户名自动取邮箱前缀。

### 5.2 重置学生环境
JupyterHub管理页 → 找到学生 → Stop Server。学生的`notebooks/`和`labs/`会保留。

### 5.3 更新实验内容
联系管理员。实验更新后需同步到所有学生home目录（目前需手动）。

## 六、诚实声明（必读）

以下限制已在各实验中如实声明，**请勿向学生隐瞒**：
1. A1/A2/A3/A4：esmini目标车冻结（ctypes限制），Ego为Python运动学
2. A5：纯Python演示，未调用esmini
3. C2：FASTSim车辆库部分车型解析异常
4. F2：OpenModelica不在容器内，用手写FMU等效
5. 所有图表：英文标签（无中文字体）

**教学原则**：真实仿真用真实引擎，演示必须标注为演示。这是本平台的底线。
