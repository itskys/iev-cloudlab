# IEV CloudLab 教师指导手册 | Teacher's Guide

> 本手册只讲**怎么教、怎么评、学生卡住怎么办**。实验目录与判据数值见《实验手册》（唯一权威版），本手册不重复罗列。
> 配套工具：`教师面板_成绩与学生管理.ipynb`（成绩/统计/图表/名册）。

## 一、课前准备清单（开课前一周）

1. **名册**：打开教师面板 → 批量导入学生名单（CSV：邮箱,姓名,学号,班级）→ 核对人数。
2. **自测**：以教师账号把第一周要讲的实验**亲自完整跑一遍**（含"试一试"改参数），确认判据能过、图能出。平台判据都经过实测，但您亲手跑过才知道学生会在哪一步停下来。
3. **告知学生**：发《学生快速上手指南》链接 + 三条硬规矩——①C/E模块先切内核；②每次改完参数要重跑保存结果的cell；③报告里引用数值必须来自自己运行的结果。
4. **演示准备**：按第五节"10分钟演示脚本"走一遍投屏流程（登录→A1→成绩面板）。

## 二、评分细则（实验报告，百分制）与 29+1 课程成绩口径

全课程成绩严格对接《课程大纲（16周）》，采用 **29+1 双轨架构**：
- **平时实验报告（60%）**：覆盖 29 门 V1.0 官方标准实验（`*_pro.ipynb`）。平台每小时自动汇总评分，以 29 门为基准分母锁定（`REQUIRED_EXP_COUNT=29`），缺交记 0 分。平台判据客观得分建议作为平时成绩的下限锚点（40%），实验报告质性分析占 60%。
- **期中测验（15%）**：第 8 周随堂开卷实操。
- **期末综合大作业 Capstone（25%）**：第 16 周《集成演示大作业（`Capstone_iev_integrated_pro.ipynb`）》，考核电池-整车-控制全栈跨域闭环验证、三维数字孪生轨迹与答辩表现。

| 维度 | 权重 | 优秀（90–100%） | 合格（60–75%） | 不合格（<60%） |
|---|---|---|---|---|
| 结果正确性 | 30% | 全部判据通过，数值与手册实测量级一致且能说明来源cell | 主要判据通过，个别数值偏差但量级正确 | 判据未过，或数值明显抄手册实测值（见防作弊） |
| 结果分析 | 30% | 能解释每个指标的物理含义；主动做理论对比（如DP 1.92 vs ECMS-like 2.14差距来源）；指出误差来源并排序 | 能解释主要指标；有理论对比但较浅 | 只有截图和数值罗列，无解释 |
| 思考题 | 20% | 回答切中设计权衡（如TTC阈值的误报/漏报权衡），有自己的参数实验支撑 | 回答基本正确但无实验支撑 | 空缺或照抄实验原理 |
| 挑战任务 | 10% | 尝试"试一试"进阶项并记录参数-效果对照表 | 完成基础"试一试" | 未尝试（不强制，但此项记0） |
| 规范性 | 10% | 图有图题、单位齐全、有效数字合理（电耗2位小数、时间2位） | 图表基本齐全 | 无单位、截图模糊、数值无来源 |

**给分锚点示例（C1）**：电耗12.5附近且说清"UDDS市区工况、低速多启停所以电耗低于高速工况"→正确性满分档；只写"结果12.5，符合要求"→合格档；写"电耗25，符合要求"→量级错误，不合格档，且应追问是否选错车型参数。

## 三、逐模块教学要点（讲什么、演示什么、盯什么）

**A 自动驾驶**（建议演示A1，其余学生自跑）
- 讲：TTC的定义与局限（只看相对距离/速度，不看加速度→A3存在的理由）；Euro NCAP对AEB的要求可引出工程背景。
- 演示：现场把A1的TTC阈值从3.0改到1.5，让学生预测结果再运行——碰撞或险情会自己说话。
- 盯：学生是否误以为目标车是"智能的"。必须点明诚实声明：目标车冻结≈静态障碍物，本模块练的是**自车决策**，不是双车博弈。

**B 交通流**
- 讲：B1标定是"用数据反推模型"的范式，和A模块"先定参数再仿真"正好相反，值得对比着讲。
- 盯：B3最容易出现"假通过"心理——图上有车在跑≠判据过。要求学生在报告中写出最大间距误差的实际数值。
- B4的冲击波波速为负，很多学生会以为算错了：负号=向上游传播，是正确物理结论，先肯定再解释。

**C 整车能量**
- 讲：C3的结论反直觉——市区工况下质量灵敏度（0.610）远大于风阻（0.210），而高速工况会反转。让学生用"动能反复启停 vs 持续克服风阻"解释，比背结论有效。
- 盯：内核！C模块不开py310-fastsim内核必报错，这是全班最高频问题，第一次课务必全班一起切一次。

**D 电池**
- 讲：D3是链1的源头，讲清"这一张CSV表会流向整车和智驾实验"，学生对后续实验的投入度会明显不同。
- D4析锂：抓住"1C时−0.05V（临界） vs 3C时−0.64V（严重析锂）"这组对比，讲快充的工程约束，不要陷入DFN方程细节。

**E 优化控制**
- 讲：E4（DP全局最优1.92）与C4（工程策略）必须放在同一节课对比：DP是"上帝视角"的标杆，工程策略的价值在于可实时实现，差距2.14−1.92就是"可实现性的代价"。
- 盯：E2的Pareto图要学生标出拐点并说明选择理由，只交一张散点图的不给分析分。

**F/G/H 工程方法模块**
- 这三个模块各用一节课讲"汽车软件工程的协作方式"：F=模型接口标准（为什么要有FMI）、G=中间件通信（话题vs服务的适用场景）、H=场景库与测试覆盖（通过率31.58%不是"失败"，是找到了算法边界）。
- H2特别提醒：通过率低≠做错了。判据是通过率落在10%–95%区间，太高反而说明变异强度不够。

## 四、学生常见误区与引导话术

| 现象 | 真实原因 | 引导（不要直接给答案） |
|---|---|---|
| "老师，A3朴素版撞了，我代码错了？" | 没错，朴素TTC不考虑前车加速度，本来就会撞，这是实验设计 | "先别改代码。把碰撞时刻前车的加速度读出来，看朴素公式里缺了哪一项" |
| "B3误差1.09，过不了1.0的标准" | 合格线是2.0m（手册判据），1.0m是已作废的旧线 | "去查实验手册B3的判据再下结论；顺便想想：为什么教学线要留0.9m余量？" |
| "C1电耗算出来25" | 多半选错车型或没加载D3电池（默认参数量级不同） | "把你加载的车型质量和电池容量打出来，对一下车型库" |
| "E2的图没有拐点" | 参数范围设得太窄，两个目标没形成权衡 | "把功率范围拉大一倍再看，前沿弯不弯？" |
| "H2通过率只有三成，是不是我AEB太差" | 模糊测试的目的就是探边界，31.58%是平台实测同量级 | "把4个边界案例挑出来分析共性，这才是这个实验要交的东西" |
| 改完参数结果没变 | 没重跑保存结果的cell，或图看的是上一轮缓存 | "从改参数的cell往下全部重跑，再刷新图" |
| 开局就报 ModuleNotFound | C/E模块没切 py310-fastsim 内核；或在A/B用了fastsim内核 | "右上角看内核名，对照实验手册的内核列" |

## 五、课堂组织建议

- **翻转课堂节奏**（2学时/次）：课前学生按快速指南自跑实验并截图自查分 → 课上前20分钟教师演示一个"改参数看现象" → 中间50分钟学生完成思考题与挑战项，教师巡视只答"卡点" → 最后20分钟用教师面板投屏全班成绩分布，点评共性问题（指实验不指人）。
- **分组**：建议2人一组共用一台投屏讨论，但账号与报告各自独立提交——判据数值随机性虽小，分析文字雷同按作弊处理。
- **10分钟演示脚本**（开放日/汇报用）：登录页（邮箱验证码，30秒）→ A1切入场景跑一遍并指出TTC曲线（3分钟）→ 打开D3→C1说明链1（3分钟）→ E2 Pareto图讲多目标权衡（2分钟）→ 教师面板成绩分布图收尾（1分钟）。全程不提"规划中"的I模块为主线，可一句话带过路线图。

## 六、成绩分析怎么做（教师面板）

1. 每两周打开面板看**每实验均分图**：均分<60的实验，下节课开头用10分钟复盘（通常是判据背后的概念没懂，不是操作问题）。
2. 看**分数分布图**：双峰分布说明班级分化，低峰群体逐个查n_done（完成数）——多半是缺交而非做错。
3. 期末用**学生排名图**核对总评，异常低分先查是否内核选错导致整批实验无结果（模式很明显：C/E全空、A/B正常）。

## 七、学术诚信与防作弊体系 (v1.0.0 全自动护航)

为保障教学公平与工程学位点评估要求，平台配备了工业级双轨学术防线：

1. **AST 抽象语法树代码查重 (`common.plagiarism_detector`)**：
   - 在教师面板中可一键对全班特定实验（如 A1、B3、Capstone）展开代码全量交叉扫描。
   - **母版指纹差分过滤**：算法自动比对官方母版 Notebook，提取自带模板骨架并完全过滤，仅比对学生自主编写、扩写或重构的算法逻辑，彻底杜绝“原样跑模板被误判为严重抄袭”的虚警。
   - 算法提取自主代码的 Python AST 语法骨架并过滤变量重命名、注释与格式混淆，计算 3-Gram Jaccard 结构相似度。
   - 相似度 $\ge 85\%$ 时自动标记为高度雷同并高亮异常代码对，生成交互式审查报告。
2. **报告数据真值一致性核验 (`common.report_checker`)**：
   - 自动解析学生 Markdown 报告中提及的指标数值（支持 Markdown 表格与行内键值对提取）。
   - 严格比对底层仿真运行记录文件（`results/<exp_id>.json`），在 5% 容差内校验一致性，杜绝"编造数据"与"硬抄手册实测值"。
3. **百份研报智能评估引擎 (`common.report_evaluator`)**：
   - 结合 35% 数据真实性 + 65% 质性机理（物理背景、动力学响应、工程权衡与批判性反思），提供百分制自动建议分与教师评语草稿。
4. **学期全量安全封存归档 (`common.semester_archiver`)**：
   - 学期末在教师面板一键打包下载全班实验数据、加权总成绩单（29门必做分母锁定）、AST 查重记录与短板热力图 ZIP 归档包。

## 八、问题上报

平台故障（登录收不到验证码、容器起不来、全班性报错）不要让学生反复重试——截图+时间点汇总给管理员。单个学生的环境问题，先让其换浏览器无痕窗口排除缓存，再上报。
